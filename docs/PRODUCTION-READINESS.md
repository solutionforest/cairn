# Tidemark v0.1 — Definition of done

Thirty-six rows. Each `[x]` names its proof (test file, CI job, or doc). The first public tag
waits for every row. Shelved features (BUILD-PLAN "Shelved") have no rows here on purpose.
Rows marked **claim** are the four DESIGN §0 claims against VaultS3 and RustFS; a release with
any of them unproven is a release of a worse VaultS3.

Legend: `[ ]` todo · `[~]` partial · `[x]` done.

## C. Durability and recovery

(crates/tidemark-engine/src/crash_tests.rs: the test binary re-executes itself, parks at a `cfg(test)`-only `failpoint!` (mid-body, blob placed, inside the commit txn, after commit; for put, put encrypted, complete, delete) and is SIGKILLed; reopen + `recover` (as `tidemark serve` does at start) leaves the old or the whole new object, never a partial version, an intact resumable upload, empty `tmp/` and a clean full-verify fsck)
